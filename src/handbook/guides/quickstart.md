# Quickstart

weave keeps structured records and written context together. A project can have tasks, a note can refer to several kinds of record, and a total can follow the values it depends on.

## Explore before you build

Open [[table:Showcase/Projects|Projects]] and choose a project. Follow a task relation, then return to the project. In [[table:Showcase/Notes|Notes]], open a note and follow its Related links. These are ordinary records in the public workspace.

The **A project and its linked work** guide walks through these examples. [[table:Handbook/Fields|Fields]] explains how each field is configured; [[space:Wiki|Wiki]] explains the design decisions behind the model.

## Make a workspace

Use the workspace rail to create a workspace of your own. An architect can add spaces, tables, fields, and views. An editor can work with records inside that structure.

For a starting structure, open [[space:CRM|CRM]] or [[space:Money|Money]] and choose **Use template**. Select your destination workspace and name the new space. The copy includes the schema and views; records and attachments stay behind. Relations outside the template space may be skipped. Review the result before adding your own data.

Prefer to build with an agent? Read **Connect an agent**, then [[table:Handbook/Guide|Agent access (MCP) in the guide list]] for the tools and permissions. Always connect the workspace you intend to change.

## Follow the public work

[[table:Development/Issue|Issues]] holds bug reports and investigations. [[table:Development/Feature|The roadmap]] shows proposed and ongoing work. [[table:Development/Release|Release notes]] describe changes by release.

weave's own issues and roadmap are kept in the weave docs workspace on weave cloud, https://weave.grunion.ai/w/weave, together with the test suites and test cases. A new install does not copy them, and bug reports filed on it go to its own Issues table. Use the test cases on weave cloud to see what is checked, then link a specific case or issue when you report a problem.
