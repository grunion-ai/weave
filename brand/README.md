# weave brand

The weave logo mark and its generation pipeline. Selected 2026-08-16 after four
exploration rounds (contact sheets in [docs/](docs/)).

## The mark — "h3"

A horizontal rope: two strands, three crossings, true alternating over-under
weave. Parametric — generated by `rope(n, pitch)` in
[build-logos.mjs](build-logos.mjs) with `n=3, pitch=8`, amplitude 8, strand
width 3.5 on a 48-unit grid. The under-strand is cut with SVG masks
(gap = strand width + 2.5), so every asset is transparent-safe.

## The loader (decision 7)

`weave-on`: both strands draw in left to right, the crossing locks in, then the
rope unweaves the same way, on a **2000 ms** loop. Generated by `loaderSvg()`
alongside the mark, from the same `rope()` and the same masks — it is the mark
in motion, not a second drawing of it.

Three things are load-bearing:

- **The crossing is part of strand A, not a third path.** The static mark lays
  the crossing over the top as its own path; under a draw-on that path has no
  honest moment to arrive, and timing it late leaves a hole in the middle of the
  mark. Mask A cuts the under-strand and then paints the crossing back in white,
  so A stays continuous through it. Two paths, one animation.
- **The cycle length is published.** `LOADER_CYCLE_MS` is exported here and
  imported by the app's contract test, because "let it finish a cycle" is only
  true while the generator and the UI agree on how long a cycle is.
- **A shown loader always completes a whole cycle.** The rope is never caught
  half-woven: the UI rounds its hide up to the end of the cycle it is in.

Consumers:

| Where | Asset | Why |
| --- | --- | --- |
| App page loads | `public/brand/weave-loader-rope.html` (`loaderRopeHtml()`) | Inlined by `initPageLoader()`. Chrome and Safari tick SMIL on the main thread, so the SMIL rope froze on every long task (Issue #390). The app shows the still strands through windows that move by transform only, which the compositor runs: each end of the dash is an anchor holding a far-side window, a square cut at the end's point and a round cap disc, and the strand inside counter-moves so it stays put. The ends ride the dash's ends frame by frame; the unweave follows Chromium's dash so it ends on the two end dots. Look settled by Kyle, 2026-09-28 |
| README hero | `assets/png/weave-loader-{dark,light}.gif` | GitHub's image proxy does not run SMIL; `brand/render-gif.mjs` builds the pair from the same generator |

## Usage rules

- **Minimum sizes:** mark 12px tall; lockup 80px wide. Below that, use the favicon build.
- **Clear space:** half the rope height (≈ 6 units at 48 scale) on all sides.
- **Never** recolor strands outside the pairs above, outline the mark, or
  rotate the horizontal mark (vertical/diagonal ropes were explored and
  rejected for the primary — see `docs/`).
- The lockup wordmark is Outfit 600; the SVG falls back to the system stack if
  Outfit isn't loaded.

## Rebuilding

```
node brand/build-logos.mjs        # served SVGs + loader -> public/brand/, the rest -> brand/assets/
node brand/render-png.mjs         # PNGs via Playwright Chromium
node --test brand/build-logos.test.mjs
```

ImageMagick cannot rasterize these SVGs (its delegate drops `<mask>`), which is
why raster export goes through a browser engine. `favicon.ico` is packed with
`magick brand/assets/png/favicon-16.png public/brand/favicon-32.png brand/assets/png/favicon-48.png public/brand/favicon.ico`.
