## v0.4.19 — 2026-09-13

- **The caret keys stay with the caret** (Issue #260): click into a long name, press End, type — and the edit landed in the MIDDLE of the value. A CX audit did exactly that and left Issue #85 named "L zzs broken: …". `End` inside an open cell was the browser's, and Chromium reads a bare End in a single-line field as *scroll to the end of the document*: the windowed grid (Issue #271) scrolled a thousand rows, recycled the row the editor sat in and dropped focus on `<body>`, while the caret never moved. The grid places the caret itself now — `Home` and `End` in an open cell resolve to a `caret` verb and the keystroke is consumed, so nothing scrolls — and only for a single-line `<input>`: a textarea's `End` belongs to the line it is on, and a select, number or date control has no caret to place, so each of those keeps the browser's key. `⇧End`, `⌥←`/`⌥→` and `⌘←`/`⌘→` are real editing commands, were never broken, and stay the browser's; at rest `Home`/`End` are still the first and the last ROW of the table. Handbook: the **In an open cell** table in the grid guide. Gates: `test/grid-keymap.test.mjs` (the open-cell verb, the three modified forms, and the resting rows), `test/grid-window-browser.test.mjs` (End in an open cell of a 1,200-row table: the caret lands at the end of the value, the window holds its scroll, and the next character appends).
- **A loop says so** (Issue #283): a formula that reached its own field the long way round — `Total` reading `Bonus` while `Bonus` read `Total` — hit the depth-8 recursion guard, which returned `null`. The cell then read like a legitimately empty one, and one level up the arithmetic turned that null into a number nobody could explain (a two-row rollup loop computed `6`). Two halves now. **At save**, an expression that closes a cycle through the table's other formulas is refused with the path — `Formula 'Bonus' would close a reference cycle: Bonus → Total → Bonus` — on `addField`, on `updateField`, on a text→formula type change (which validated nothing), and in `checkFormula`, so the dialog says it before the save does; the walk only follows formula→formula edges, every other type being a leaf, and a field that is not in the table yet is matched by the name a live formula still calls it. **At read**, a computed field that re-enters itself for the same row answers with `#CYCLE:` and the path instead of null — fields alone when the loop stays on one row, `Alpha › Double → Alpha › PeerSum → Beta › Double → Beta › PeerSum → Alpha › Double` when it travels between rows, because the rows are what closed it — and the marker travels rather than being consumed: a formula reading a looping field reports the loop, a rollup reports it rather than summing it, a lookup carries it out, and no display costume is painted over it. The loop that no save can see — one that closes through a rollup or a lookup, which needs two rows pointing at each other — is exactly what this half catches. The stack unwinds in a `finally`, so an erroring formula never leaves the next read looking cyclic. Gates: `test/formula-cycle.test.mjs` (11 — the four save doors, the REST 400, the rollup loop through two rows, the row outside the loop, the unwind, and `references()` over both arms of `if`).
- **A sort orders the value, not the costume it wears** (Issue #279): uno's `Agent/Sessions` — 720 rows, sorted Created descending, Created a `date` field wearing the `long` format — put "Sep 9, 2026 9:51 AM" above every row created on Sep 12, so an hourly writer's rows read as missing. Both comparators had been handed the painted string: the engine's `#pathValue` returns display values, and `query`'s sort compared those, while `public/app.js` compared `item.fields[…]` for the grids that hold every row. `"Sep 9"` beats `"Sep 12"` as text, `"15,829,984"` loses to `"900"`, and `"$17.25"` beats `"$9.50"`. Sorting now undresses the two types whose painted form does not order the way the value does — a number stays a number, a date stays its stored instant — and leaves every other type on its display form, because for an option, a state or a joined relation the name *is* the value. It is the rule a formula already read by (`#resolve`) and the one the Handbook's date guide already promised ("comparison, sorting and date math all run on the stored value"). Filters are untouched: `contains "Sep"` still reads the costume. Both halves changed together, so a paged grid (server-side sort, Issue #271) and a whole one land in the same order. Gates: `test/sort-values.test.mjs` (5 — date, number through separators and currency, select by option name, empty cells last, the filter guard), `test/sort-values-browser.test.mjs` (2 — the same table read through the server's sort and through the grid's own).

## v0.4.18 — 2026-09-12

- **Every document keeps its history** (Feature #225, Kyle 2026-09-12: "all weave documents should have a built-in version history", so decklet can drop its in-file snapshots): `setDoc`/`appendDoc` overwrote `entity.docs` and the prior text survived only as an undo before-image (popped on undo) and a length delta in the feed — nothing could bring a past document back. A new `doc_revisions` table beside the entity blob (mirrored in the Durable Object store) now takes a snapshot of the new text on every document write — `setDoc`, `appendDoc`, an `updateEntity` naming a document, a create born with one. Writes by one actor to one field inside ten minutes fold into the newest snapshot (the activity feed's own window, Issue #32), so a typing session is one revision and the 600 ms autosave never builds a keystroke log; identical text records nothing; 200 per document, oldest trimmed. A document that predates the log gets its prior text as the baseline on its first write. `listDocRevisions` is metadata only, newest first (`seq`, `at`, `actor`, `len`); `getDocRevision` carries the text; `restoreDocRevision` is an ordinary `setDoc` recorded fresh, so a restore never overwrites the session it steps back from, and undo records fresh too. A purge drops the row's revisions; the trash keeps them; an export carries the current text only. Doors: `GET /api/entities/:ref/doc/revisions?field=`, `GET …/revisions/:seq`, `POST …/revisions/:seq/restore`; `weave doc-revisions` / `weave doc-restore`; `weave_doc_revisions` / `weave_doc_restore`. In the chrome, a `lucide:history` control beside the source toggle shows once a document has more than one revision and opens a panel inside the section — newest first with relative time, actor and size delta; a row renders that revision read-only in place of the editor under a **Viewing revision** bar; **Restore** writes it back and re-renders, **Back** or Escape returns. Both themes. Handbook: the `document` page's **History** section. Gates: `test/doc-revisions.test.mjs` (22 — the store contract on memory, sqlite and the DO shim; coalescing, baseline, cap, restore, undo, purge; the three doors), `test/doc-history-browser.test.mjs` (3, both themes).
- **Paste into a relation cell links by name** (Feature #224): Feature #220's plan refused a `relation` column, so once Feature #221 let ⌘V reach the cell, a paste into `Owner` or `Peers` wrote nothing and the toast named the column. A paste now links: the grid fetches the related table's rows first — the same `POST /api/tables/:id/query` the record picker runs — and the pure plan matches each label to a row, a copied weave block by id, otherwise the exact name (trimmed, case-insensitive), then `#12`. Matched ids ride the existing `bulk set` (the engine's `updateEntity` already replaces a relation's whole set from an id list, and a single-cardinality field takes one), so a paste is one call per distinct value set with one Undo, and copy is untouched. A label that names no row is counted and named in the toast (`1 unmatched (Nobody)`) beside the unreadable count; a cell whose labels all miss is dropped rather than emptied. Without the rows to hand — a fetch that failed — the column refuses by name as before. Handbook: the "What the types force" list under "Ranges, fill and paste". Gates: `test/grid-range.test.mjs` (+8 pure: `resolveRelation`, the relation plan, the toast), `test/grid-range-browser.test.mjs` (+3: copy → paste → chips → Undo; a TSV label with one stranger; a single relation from `#id, name`).
- **Passkeys: people sign in without a token** (Feature #222 part 2, door B; Feature #208; Feature #141 §3): with `requireAuth` on, a browser had no way in that did not involve pasting a `wv_` secret. `GET /auth` is now a sign-in page served through the wall — one button, a discoverable passkey, no username step — and `/api/auth/*` carries the two WebAuthn ceremonies, verified with `node:crypto` and a 60-line CBOR decoder, no dependency: `none` attestation, ES256 or RS256, clientDataJSON type/challenge/origin, `rpIdHash`, user presence, the signature over `authData || sha256(clientDataJSON)`, and a counter that must advance once either side counts. A verified sign-in mints a 30-day sliding session in an `HttpOnly; SameSite=Lax` cookie (`Secure` under an https `WEAVE_ORIGIN`), stored as its sha256 beside the account; the wall accepts it as it accepts a Bearer token, and a Bearer token wins when both are present. A dead cookie sends a page to `/auth?next=…` and an API call to a JSON 401. The first passkey starts from the CLI: `weave account invite <name>` prints a one-time URL good for 15 minutes; `account sessions`, `account revoke-session --all`, `account remove-credential` are the lost-device verbs, on the CLI and on `weave_accounts`. `/auth` doubles as the account page — passkeys, sessions, sign out, sign out others, add this device. `WEAVE_ORIGIN` is required when auth is on off loopback (`serve` refuses to start without it); `WEAVE_TRUST_PROXY=1` lets the in-memory rate limits (10 options and 5 failed verifies a minute per address) read `X-Forwarded-For` behind Railway or Fly. Sessions and invites never leave through an export. New Handbook guide **Door B: passkeys**. Gates: `test/webauthn.test.mjs` (fixtures built in-test from a software authenticator, every negative case), `test/auth-session.test.mjs` (engine + routes: invite → register → wall → logout → wall; expiry, revocation, rate limits, Bearer precedence), `test/auth-passkey-browser.test.mjs` (Chromium's virtual authenticator through the real page).
- **`weave backup` and `weave restore`, with a nightly that needs one env var** (Feature #222 phase 3, Feature #209, Issue #250): the only backups were a laptop script into iCloud and the JSON export the Handbook warns drops attachments. `weave backup` now takes the whole data directory — every workspace `.db` through `VACUUM INTO` from a throwaway connection, so a server mid-write neither blocks it nor lands in it; `files/`; `keystore.json` — into one POSIX tar with a `manifest.json` last: entries, a sha256 per entry, entity counts per workspace, the weave version, and the orphan report. `keystore.key` never goes in; its material seals the archive instead (AES-256-GCM under a scrypt key), or `WEAVE_BACKUP_PASSPHRASE` / `WEAVE_KEYSTORE_PASSPHRASE` when set, and with none of the three the archive is a plain tar and says so. A reference to a blob that is gone from `files/` (Issue #250 found fifty-six) is counted and listed, never fatal. `--dest s3://bucket/prefix` (or `WEAVE_BACKUP_DEST`) uploads with a SigV4 signer written on `fetch` and `node:crypto` — R2 via `WEAVE_BACKUP_ENDPOINT`, B2, S3 — and prunes past the newest thirty archives; the signer reproduces the three worked examples in the S3 reference. `weave restore <archive|s3://…|https://…> --data <dir>` verifies every sha256 against the manifest, refuses a database a server holds open (a `-wal`/`-shm` sidecar or a `BEGIN IMMEDIATE` that cannot take the lock) and an existing target without `--force`, then unpacks; `weave restore <ref>` stays the entity verb. `weave serve` with `WEAVE_BACKUP_DEST` set runs the backup daily at 04:00 UTC on an in-process timer chain (Railway cron services cannot share the volume), writes `backup-completed` / `backup-failed` to the audit log, and `/api/health` carries `backup: {lastAt, lastStatus, nextAt, dest}`. Handbook: **Backup and restore** — the three variables, R2/B2/S3 examples, retention, the rehearsal, `keystore.key`, Litestream as the upgrade. Gate G4: `test/backup.test.mjs` (23 cases — round trip with two workspaces, an attachment byte-for-byte, an orphan and the keystore; live-writer safety; the ustar writer against `tar -tf`; the signer vectors; upload, list and prune against an in-test bucket; the scheduler on a fake clock; health).
- **The dock follows the click; the page stays** (Issue #276, Kyle 2026-09-12): a relation chip pointing at a row in another table used to tear the table down, push `#/table/<other>` and dock the row beside the *other* table, so the crumb restarted there and the reader lost the grid they were reading. `openEntity` now docks the row beside the table under the reader whatever table the row lives in, pushes no history, and only travels when there is no table page at all (home, a space, activity, ⌘K from there). A hop from inside the dock extends the dock's chain across tables — each frame carries its own table, the state carries the anchor — and the dock's crumb is that chain run through `entityCrumbs`, so the table crumb appears where it changes (`Deals › Acme › Contacts › #4`) and a new back arrow (or Esc) walks it one frame back; a frame already on the chain cuts back to it. `?e=<id>` on the current table hash survives a reload for a foreign row, which renders from its own table. The expand arrow still lands on `#/entity/<id>`. Gates: `test/entity-dock-browser.test.mjs` (4 new cases), `test/entity-dock-default-browser.test.mjs` (expectations moved to the page-stays rule, plus the no-table-under-you case), `test/breadcrumbs.test.mjs` (`dockCrumbs`). Handbook: the grid guide names the rule.
- **The auth wall covers every route, and an export keeps its secrets** (Feature #222 phase 0, Issue #230, Feature #194 problem 2): `requireAuth` and the role caps applied to `/api/*` only, so with auth on every entity page, `doc.html`, `entity.pdf`, `deck.html` and the app shell itself were readable by anyone who reached the port. With `requireAuth` on, every route now needs a Bearer token; a browser gets a small page saying the workspace requires authentication, an API call keeps the JSON 401. The doors that stay open: `/api/health`, a view's share link, the passcode applet under `/t`, and the static CSS/JS/font/image assets a sign-in page will need. A reader token may read any page and write at none. `GET /api/export` — and `weave export`, and the MCP tool — no longer carry account `tokenHash` values or view share tokens: an imported account keeps its name and role but verifies no token until re-created, an imported view arrives unshared until shared again. `POST /api/import` is a schema write and needs an admin token. Gate: `test/auth-wall.test.mjs` (six cases; the route list is derived from `src/routes.js` so a new route cannot hole the wall unnoticed).
- **Grid cell clipboard follows the selection** (Feature #221, Kyle's "B+", 2026-09-12): a click opens a cell exactly as before, and `⌘C`/`⌘V` follow the selection — text selected in the open control is the browser's own copy and paste; with no selection (a bare caret, a picker's popover, a checkbox, a resting cell) they take the **cell**, typed, through Feature #220's `bulk set` with one Undo. A clicked text-like cell opens with its whole value selected, and a second click places the caret. Chips, url links, the `#id` link, checkbox flips and pickers are untouched. Pure rule `WeaveGridKeymap.clipboardTarget` (`test/grid-keymap.test.mjs`); gestures in `test/grid-range-browser.test.mjs`; the Handbook's grid guide names both rules.

- **Grid ranges: shift-select cells, drag-fill, and copy/paste values** (Feature #220). Kyle: "I need a better way to select, drag to duplicate, copy or paste values — like single or multi select dropdowns — across cells." #134 made the cell rest as a value and #132 gave a run of ROWS one write; both stop at the row, so copying one Status onto the next four meant reopening a dialog and re-picking. A rectangle of cells is now a **range**: `⇧` and the arrows grow one, or the pointer drags one, and `Esc` lets it go — rows first when both are up, so Space and `⇧↑↓` still mean exactly what they meant. The blue square on the range's bottom-right corner is a **fill handle**: drag it down a column or across a row and the range's values are written over everything it covers, one axis at a time. `⌘C` puts TSV on the clipboard for a spreadsheet and the same block typed for another weave tab, which is what makes a select paste as an option rather than as a word; `⌘V` tiles the block to fit whatever it lands on, so one copied cell fills twenty. Select, multi-select and workflow paste by **option identity** — the id carries over within a table, the label goes into a different one, and a label that names no option there is refused rather than invented. A multi-select is a replacement, never a merge. A formula, rollup, lookup, view, relation or document column takes no paste: the cell refuses and the toast names the column, following `bulk`'s precedent of saying what did not land. Text from a spreadsheet is read in each column's own terms (`false` is false, not `Boolean('false')`), and a cell that will not read is dropped and counted while its neighbours land. The write is the existing `bulk set`, one call per distinct set of values — so a fill down twenty rows is one write — and the toast carries an **Undo** that steps the whole thing back. `bulk set` gained `changed` beside `done` for that: a row that already held the value pushes no undo entry, and counting the rows it merely visited would step past this write into somebody else's. Not built: `⇧`-click, which stays the browser's "open a window" on every navigating surface (`023b777`); the range comes from `⇧`-arrows and the pointer drag instead. Handbook: "Ranges, fill and paste" under the grid guide. Tests: `test/grid-range.test.mjs` (36 pure), `test/grid-range-browser.test.mjs` (13 browser), plus 6 keymap cases and 2 engine cases.

## v0.4.15 — 2026-09-09

- **A test that fails once gets asked again** (Issues #44 and #239): `npm test` runs through `scripts/test.mjs`, which re-runs the files that failed — only those — and lets the second answer stand. Sixty-eight of the 192 suites drive a real Chromium, and under the full run a wait for a menu to paint can lose to a thirty-second budget: a different browser case failed on roughly every other full run while the same file alone was green eight times out of eight, and each one cost a Verified −1 on a change that was fine plus a re-gate to prove it. A regression is not a coin toss, so a broken file fails both times and the vote stands; the retry can only rescue a failure that did not reproduce. Nothing green pays for it — there is no second run on a passing suite. The flake is not absorbed either: every retried file is named on stdout under `# RETRYING` and `# RETRIED`, inside the `tail` that `weave-review.sh` quotes into its Verified +1, so a suite that keeps needing the second chance says so in the review that passed it. Capping browser concurrency was the other candidate and the measurements refused it: the 68 browser suites take 110 s at `--test-concurrency=4` against 66–70 s at 10, 16 and 24, and were green at every one of those over eight runs. `npm test` is now the one command in the README, CONTRIBUTING, AGENTS.md, the PR template and the GitHub matrix. Gates: `test/test-runner.test.mjs`, `test/extras.test.mjs`.
