# Changelog

weave's tracker (the Development space in the weave workspace) is the changelog of record — every Feature and Issue row carries its evidence. This file is the release-notes digest.

## v0.4.80 (2026-10-07)

- A rollup or a lookup that draws rating icons now opens wide enough for all of them, and holds that width as its resize floor, the way a rating column has since Issue #404. A max-7 rollup drew 104px of icons in an 80px cell before. (Issue #564)
- Opening another record in the dock starts it at the top. The dock reuses one scroller across records, so the previous record's offset carried over and the new record's title sat off screen above the reader; an edit or a refresh of the record on screen still holds its place (Issue #623).
- A lookup of a rating over a to-many relation now draws one group of icons per related row instead of printing the numbers, and a related row with no rating keeps its slot as an unrated group. The chip, the card and the field dialog's sample draw it the same way. (Issue #377)
- Checklist items in a document wrap between words. Before, Vditor's `word-break: break-all` let a line end mid-word ("sen / ds"); a URL longer than the line still wraps inside the column (Issue #715).

## v0.4.79 (2026-10-07)

- Three browser suites launched their own WebKit or Chromium through `import('playwright')`, outside the shared harness. Those pages never saw `WEAVE_CPU_THROTTLE`, so the recipe DEVELOPMENT.md gives for a gate-only red could not reproduce one in `frozen-ground-browser`, `phone-shell-browser` or `editor-math-browser`. All three now ask the harness for the extra engine through `engineOf(name)`, which throttles it and closes it with the suite: the same file runs 13 s unthrottled, 16 s at throttle 4 and 36 s at throttle 20, where before the WebKit half ran at full speed whatever the setting. `test/browser-harness.test.mjs` now holds every `*-browser.test.mjs` to the harness, not only the ones its old pattern matched.
- A first-paint wait that misses now says what the page had instead. `painted()` reports the hash, whether the route skeleton is up, what stands in `#main`, how many grid rows the page counts and the toast text, so a 30 s timeout on `.wv-grid tbody tr.entity-row` reads as a diagnosis rather than a bare budget. The cases on `#711` do not reproduce on this main: the cause was the route skeleton painting over a drawn page, fixed under Issue #713 and shipped in v0.4.78 (Issue #711).
- Two browser cases stop losing the Verified gate to machine load. Both waited on a clock instead of the event they assert: `bulk-settle-browser` held the eight-row State change to a 600 ms wall clock, and `doc-autosave-phone-browser` gave the leave-triggered write a 400 ms request window. The bulk case now waits for the eight rows to leave the filtered view, the toast to read `Set 8`, and the grid's animations to finish. It keeps the counts it was written for: one `POST /api/bulk`, one page re-read, nothing else. In the phone cases the 600 ms autosave debounce is cancelled inside the page, so the only write that can reach the server is the one the leave handler sends, and the wait on it is a hang guard at 15 s. Both files pass at `WEAVE_CPU_THROTTLE=40`, where the old waits went red (Issue #619).
- A browser case no longer loses the node it just waited for. `system-tables-nav` waited for `#main input.view-title` and then read it back through `page.$eval`, which resolves the selector a second time; `drawDatabase` opens with `main.replaceChildren()` and the view header settles on a ResizeObserver after that, so the read could land in the gap and throw. Under gate load the gap was wide enough to cost two unrelated changes a Verified vote. Twenty-eight reads across seventeen browser suites had the same shape and now go through `page.locator(selector)`, which re-resolves on each attempt. `test/browser-read-reresolve.test.mjs` fails on any new one, and `system-tables-nav` carries a case that forces the repaint and shows both halves: the single-shot read throws, the locator read waits it out (Issue #637).

## v0.4.78 (2026-10-07)

- A table view can show as a **List** (View menu, **Layout: Table · List**): the same rows, filters, sorting and density, each row drawn as the table's Chip. The new **Group** button sets up to three ordered levels (select, workflow, toggle, checkbox, link or date by grain), each headed by a label or, for a link, the linked row's Chip, in option, table or A to Z order; every group folds. **Completed by** draws a checkbox field on each row and moves ticked rows to a folded **Completed · N** group; **Nest by** indents rows under a Parent link, with **Tab** / **Shift+Tab** and sideways drags. With no sort, drag sets a manual order saved in the view; a sort orders rows inside each group. Each innermost group ends in an add row that fills every group value and equals-filter and reads a typed date. The footer reads `3 of 8 to-dos · 1 completed`. All of it saves into the view and reaches agents through `weave_table_view` (`layout`, `group`, `completedBy`, `nest`, `collapsed`, `order`), the CLI and REST; the Workspace/Views row gains Layout and Group (Feature #276).
- A rollup takes the number costume of its own (`format`, `decimals`, `unit`, `display` `bar`/`ring`/`heat`, `scale`, `color`), set on create or through `weave_update_field`, and a number aggregate over a checkbox or toggle counts a tick as 1: `avg` of a Done box is the share done, so a progress bar on a Trip's Chip is one rollup field (Feature #276).
- A table opened with a record in the dock no longer turns back into the loading skeleton. The route skeleton fired at 150 ms even when the table had already drawn, because only the end of the whole route (which waits for the docked record) cancelled it; it painted over the rows and stayed. The skeleton now stands down the moment the page puts anything in the main panel. This was the cause of the `phone-shell-browser` WebKit timeouts in the gate (Issue #713).
- Known limits of the List layout in this release: the Group button shows only in List layout (Table keeps the grouping and ignores it); the Statistics panel's Group by draws its fields from the same list but still groups one level; a list draws every row at once with no paging, and a link level reads at most 500 linked rows for its empty groups and table order.

## v0.4.76 (2026-10-07)

- The sidebar foot shows who is signed in: an account chip under the stats line with initials, the account name and the role in this workspace (Observer, Editor or Architect). It opens a menu with `Sign out of <workspace>` and `Sign out everywhere`, which posts `/w/<name>/api/auth/logout` for every workspace in the rail and lands on the sign-in page. A signed-out walled workspace shows `Sign in`; an open workspace with nobody signed in shows nothing. No email is shown (Feature #281).
- A code block at rest no longer paints a 2px grey square above its top-left corner. The hidden source box keeps no border until the block opens for editing (Issue #704).
- The document editor booting on a host already in the dock, which painted its body for 72 ms and then took it away, is on the flicker ratchet (Issue #634).
- Linking a relation opens the ⌘K search scoped to the relation's target tables instead of a Name-only list: it matches any text on the row, shows linked rows checked, replaces a to-one value on pick, toggles a to-many set until `Esc` or `Return` on an empty box, and ends with `+ New <term>`. `+ Link existing`, the relation editor in the grid and on the record, and the selection bar's `Link to…` all use it, and none preloads the target table. `GET /api/search` takes `tables=<id,...>` (Issue #703).
- `weave_ontology` reads the schema in one short call, and the MCP primer's first line sends an agent there before anything else. `{depth: "outline"}` (the default) gives one line per table, grouped by space: short field types, option and state names, relations as `name -> Target (inverse)` with `*` for many, and lookups, rollups and formulas as `name = short form`. On the weave docs workspace it is 5,250 characters, against 103,226 for `weave_schema`. `{concept: "Issue"}` reads one table in full with every field's description, and `{since: "<etag>"}` answers only the spaces whose schema changed. Each space now carries a schema version counted from the structural audit log, so a row write moves nothing; the outline ends with the workspace etag. The same reads are `GET /api/ontology` and `weave ontology` (Feature #277).
- A signed-in browser stays signed in while it is used: each time the server extends a session (at most once a minute), the response reissues the `wv_session` cookie with the same token and a fresh 30-day lifetime. Before, the cookie was written once at sign-in and the browser dropped it on day 30 however active the person was (Issue #710).
- A space is now defined as the unit of meaning in a workspace: the tables of one area, addressed as `Space/Table`, under one schema version. The ONTOLOGY export, the glossary in `docs/ONTOLOGY.md` and a new **The space** section in the Handbook's *Making a workspace your own* guide carry the same definition (Feature #278).
- On a phone a checklist box in a document is a 44px tap target with an 18px box drawn inside it, so a thumb that lands 10px off still ticks the task. The text beside it still takes the caret, and the desktop box is unchanged (Issue #705).
- On a phone the formatting bar stays on top of the keyboard when Safari pans the page under it. The bar now re-places itself on the visual viewport's scroll as well as its resize (Issue #706).
- The iPhone undo and redo gestures (shake, three-finger swipe, the Undo key on an iPad keyboard bar) step through the document editor's own history. Before, they reached the browser's undo, which had nothing to take back (Issue #707).
- Each workspace keeps its own browser session, in a cookie named `wv_session_<workspace id>`. Signing out of one workspace ends only that workspace's session, idle expiry of one leaves the others signed in, and **Sign out of every workspace** on `/auth` (`POST /api/auth/logout?everywhere=1`) ends them all. Removing an account ends its sessions in that workspace at once, and the next visit there answers a page saying access was removed instead of a sign-in redirect. A plain `wv_session` cookie from before this change is still read for one release and moves to the new name on first use; a session on the hub root still opens member workspaces until hub root removal lands (Feature #280).

The whiteboard reads the same four forms mermaid does and wraps the label on them (Issue #471).

## v0.4.71 (2026-10-06)

- **Hiding a field leaves the grid on the click** (Issue #328): every eye flip waited for its `PATCH`, then a `GET /api/schema`, then a full table query before the switch moved or the column went anywhere. On a loaded host, where each of those calls took seconds, the gesture read as broken. A hide now repaints the rows the grid already holds, one column lighter, before the write goes out: zero reads, and the switch moves on the click in both popovers. The write still queues behind `eyeWrites` in the order the flips were made (Issue #243), and the grid is read back only when the table disagrees with what was painted, which is how a hidden frozen column or a field added elsewhere still settles. A show reads once, as before: it needs the column's values. Measured on a copy of the `uno` workspace, `Agent/Sessions` at 1,791 rows: click to the column leaving the grid drops from 68-153 ms to 19-31 ms, with the PATCH, the schema read and the table query all moved off that path, and a show stays where it was at 61-80 ms. Gates: `test/fields-popover-browser.test.mjs`, `test/eye-live-rows-browser.test.mjs`, `test/ui-contract.test.mjs`.
- **A schema read counts rows in one pass** (Issue #560): `describeSchema` put each table's `entityCount` together by calling `listEntities(db.id)`, which walks the whole entity map and filters on `dbId`, so a page load cost tables times rows: about 50 tables by 6,078 rows on the weave workspace. `GET /api/tables/:id` and the search's table hits paid the same. A benchmark of v0.4.52 inside a 1 vCPU container measured a schema read at 45 to 67 ms at 8.4k entities, against under 5 ms at 4,389. The engine now walks `state.entities` once per schema read, buckets live rows by `dbId` into a Map (`#liveRowCounts`), and reads each table's count from it; `universalSearch` reads the same Map for its table hits, and builds it only when a table name matched. At 50 tables by 6,000 rows `describeSchema` drops from 30.4 ms to 0.89 ms a call. The count is still derived from the rows on every read rather than held as a maintained counter, so it cannot drift when a row is trashed, restored, purged or moved between tables. Gate: `test/schema-count-scan.test.mjs`.
