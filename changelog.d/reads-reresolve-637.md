- A browser case no longer loses the node it just waited for. `system-tables-nav` waited for `#main input.view-title` and then read it back through `page.$eval`, which resolves the selector a second time; `drawDatabase` opens with `main.replaceChildren()` and the view header settles on a ResizeObserver after that, so the read could land in the gap and throw. Under gate load the gap was wide enough to cost two unrelated changes a Verified vote. Twenty-eight reads across seventeen browser suites had the same shape and now go through `page.locator(selector)`, which re-resolves on each attempt. `test/browser-read-reresolve.test.mjs` fails on any new one, and `system-tables-nav` carries a case that forces the repaint and shows both halves: the single-shot read throws, the locator read waits it out (Issue #637).
