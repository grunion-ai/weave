- **One meta tag style names a field type** (Issue #773): `.term-tag` set the monospace face and `.wv-tag` set none at all, so the same 11px secondary type word came out mono in the field editor tray and sans on every other surface. `.wv-tag` now declares the face once, `font-family: var(--tblr-font-sans-serif)` with `font-size: var(--fs-meta)` and `color: var(--tblr-secondary)`, and `.term-tag` is gone: the plural row builds a `.wv-tag` like everywhere else and keeps its 44px right-aligned column through `.term-plural-row .wv-tag`, a parent rule, so layout is the parent's business and the face is the tag's. Sans won on call sites, since the row's own fix shape kept the `.wv-tag` name and asked `term-tag` to give up only its font; it is also the face the surrounding field names and labels already use, and the type word reads as a label rather than as code. The row measured 19 `.wv-tag` uses against 9 `.term-tag` at v0.4.88; Issue #775 has since taken the computed type words off record field rows, so the live counts are 4 against 1, and the two faces were the only thing left to settle. `tools/ui-catalog` drops its now-dead `term-tag` entry.
