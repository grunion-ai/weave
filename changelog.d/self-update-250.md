- **The hosted instance updates itself in place** (Feature #250): `weave supervise` with `WEAVE_AUTO_UPDATE=1` holds the port and runs `weave serve` as a child worker. Every ten minutes it asks GitHub for the latest release; a newer tag whose commit is on `grunion-ai/weave` main is downloaded, unpacked to `releases/v<version>/` beside the workspace, started as a second worker on the same SQLite files and checked on its own `/api/health`. Healthy, it takes new requests, the old worker drains and exits, and only then does the new one write its open-time migrations (the engine's `deferMigrations` holds every save until that point, and the supervisor holds writes for that moment instead of failing them). The supervisor forwards HTTP rather than TCP, so no client keep-alive socket closes mid-swap. A release that is off main, fails its health check or carries the wrong version inside is recorded and not retried; `/api/health` carries `supervisor.release`, `dir`, `lastSwap` and `failed`. Unset, `supervise` is `serve`. The "Deploy: Railway" guide gains step 7 with the start command. Gate: `test/supervisor.test.mjs` (zero failed requests across a swap under a request loop, an unhealthy release leaves the old worker serving, an off-main tag is refused before download, migrations wait for the old worker's exit, opt-in only).
