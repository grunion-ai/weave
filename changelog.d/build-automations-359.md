- A table in a build spec takes `automations`: rules in the Workflows Script shape (`{name, trigger, actions}`, fields and states written by name, `on: false` to build one Off). `weave_build`, `POST /api/build` and `weave build` create each rule after the table's records, a dry run reports a rule that would read Setup incomplete at its path with the reason, and a re-run keeps a rule of the same name. The Work starter now ships a Done on date and one rule, built On, that stamps it when a task reaches Done (Feature #359).
