- A new relation's inverse field takes the source table's name as written, so a table named `Action Items` gives `Action Items` instead of `Action Itemss`. On the many side it uses the plural term set on the source table's Name field, cased like the table name (`Deal` with the term deal/deals gives `Deals`); with no term, or on the one side, it keeps the table name. An explicit inverse name still wins, the field dialog's placeholder previews the same name, and existing fields keep their names (Issue #1262).
