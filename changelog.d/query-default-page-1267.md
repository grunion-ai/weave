- `weave_query`, `POST /api/tables/<table>/query` and `GET /api/tables/<table>/entities` answer 200 rows a page when the caller names no `limit`, and the answer carries `nextOffset` while rows remain, so an agent pages instead of pulling a whole table. `limit: -1` reads the table whole, as on `weave_audit`. `weave_query` also defaults `relations` to `chip`, sending each related row's summary once; `relations: "full"` keeps the embedded summaries. On the weave workspace's 3,980-row Case table, a `weave_query` with no limit drops from 18,915,798 bytes to 483,895, and the same REST call to 1,582,427 (Issue #1267).
