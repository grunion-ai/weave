- **Browser attachment uploads stream to disk instead of blocking the server** (Issue #1428): a 9.5 MB attachment sent as base64 inside JSON held the event loop for 181 ms while the server parsed the body, decoded it and wrote the file with a synchronous fsync, stalling a parallel health check by 126 ms. The browser now prepares a bounded upload with `POST /api/uploads` and sends the file as the raw body of `PUT /api/uploads`, which the server writes chunk by chunk to a staging file beside the workspace, fsyncs with the async API and renames into place before the record commits. A small preview rides along in the grant. The JSON attach routes stay for MCP and API callers, and the 10 MiB limit now counts the file itself, without the base64 overhead. Gate: `test/upload-stream.test.mjs`.
