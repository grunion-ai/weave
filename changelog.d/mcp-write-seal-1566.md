- MCP seals a reply by where its text came from, not by the tool that sent it. A write reply that echoes stored text, such as the stored name an update, link, state change, delete or restore answers with, a verbose record, an undo list or a field's stored description, now arrives inside `<weave_data>` like a read. A reply made only of the strings the caller sent, ids, timestamps, revisions and field types stays bare, and so does weave's own guidance: `hints`, `next` and `weave_call` help. A read that finds nothing now answers bare (Issue #1566).
