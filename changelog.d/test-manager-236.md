- **One test queue per machine, and one warm browser** (Feature #236): `npm test` no longer runs the suite in the calling process. It queues a job with `scripts/test-manager.mjs`, a per-user FIFO shared by every worktree, which runs one job at a time in `scripts/test.mjs`'s existing lanes and admits it only with 10 GB of free disk, 10% of memory available and a one-minute load under twice the cores; a waiting job prints the reason. The manager keeps one Playwright browser server warm, and each browser suite connects to it with its own contexts, so closing one suite cannot close another's. A raw `node --test` browser suite leases the same queue rather than launching Chromium beside it; a suite pinned to another engine (`engine: 'webkit'`) still launches its own. A job is hashed at enqueue, start and finish, and a worktree that changed during the run turns a pass red. New flags: `--targeted <file ...>` refuses an empty selection, `--affected [--base=<ref>] [--plan]` picks the files a diff can reach and says why (shared code, UI and unknown paths mean the whole suite), and `--status`, `--cancel=<id>`, `--stop` and `--timeout=<ms>` reach the manager. An admitted job times out after one hour by default, the gate's cap, and a disconnect or a dead manager reaps the job's process group and temp files. A job never admitted within `WEAVE_TEST_QUEUE_WAIT_MS` (default 30 minutes), or cut off by a manager stop, prints `# TEST MANAGER NOT ADMITTED: <reason>` and exits 75, so a gate can tell a run that never started from a red one. A raw browser suite's lease carries the admission overrides, and one process shares one counted lease across its `launch()` calls. The manager's socket directory is keyed on a hash of its source, so an older manager never serves newer code. Gate: `test/test-manager.test.mjs`, `test/test-manager-admission.test.mjs`, `test/test-selection.test.mjs`, `test/browser-manager.test.mjs`, `test/browser-manager-lease.test.mjs` and `test/test-runner.test.mjs`.
