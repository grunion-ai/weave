- **A fresh hosted instance opens no admin to the internet** (Issue #472): while an instance has no accounts and a workspace has never had `requireAuth` set, `weave serve` answers a request on any public host name with `401` (API) or the sign-in wall (pages), so `POST /api/accounts` and `PATCH /api/workspace` from a stranger no longer make them admin the moment a domain points at the service. A request on `localhost` from the same machine or a private network, with no proxy header, still gets in without an account, so a first local run and Docker on a laptop work as before; `/api/health`, `/start`, sign-in and the legal pages stay open, and the first sign-in at `/start` still creates its workspace. The new `WEAVE_SETUP_TOKEN` (32 characters or more) makes the first account over HTTPS with no shell: `POST /api/accounts` with it as the bearer works only on a workspace with no accounts and turns that workspace's `requireAuth` on. An operator who set `requireAuth` off on purpose keeps an open instance. The Deploy: Railway guide makes the first architect with the setup token and says the wall is per workspace. Not covered: an admin token minting a passkey invite over HTTP (row item 4).
