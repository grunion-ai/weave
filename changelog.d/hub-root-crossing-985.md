- **A root session opens another workspace only where it belongs** (Issue #985): any session on the default workspace counted as signed in on every other workspace, with its root role, so a root editor or observer could open a walled workspace that never gave them an account and find its rows through `?all=1` search. A root session now crosses into a workspace when the same sign-in identity holds an account there, and acts with that workspace's role, or when it is an architect of the root, who already runs every workspace's lifecycle. Everyone else gets 401 there and no search hits from it. Gate: `test/auth-workspace-sessions.test.mjs` (a non-member workspace refused, members opened with their own role, `?all=1` scoped to members) and `test/security/hub-routes-root-gate.test.mjs` (a root reader or writer session cannot open `secret` or find it; the root admin still can).
