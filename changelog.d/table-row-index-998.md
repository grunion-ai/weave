- **A table query reads its own table, not the whole workspace** (Issue #998): the engine keeps a per-table row map beside `state.entities`, updated on create, the create rollback and hard delete, and rebuilt whenever the state object is replaced (load, refresh, import, rollback). `listEntities`, the query path, permalink and `#id` lookups, the registry row lookup and the workflow row list read it. `#queryIn` walks the table once and derives the live count, `countAll` and `trashCount` from that one pass. A 100-row query in a 50,000-row workspace went from a 109.8 ms median (336.3 ms p95) to 3.6 ms (17.2 ms p95) on the same machine. Gate: `test/engine-table-index.test.mjs` (no whole-workspace enumeration, fewer than 200 rows read, a 30 ms p95 budget, and the map following create, trash, restore, purge, undo, failed create and import).
