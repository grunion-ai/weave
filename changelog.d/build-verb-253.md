- **Build a workspace outline in one call** (Feature #253): `weave_build` (MCP), `POST /api/build` and `weave build <spec.json> [--dry-run]` take one short spec of spaces, tables, fields, relations and rows and run it through the existing verbs in dependency order: workspace name, spaces, tables, plain fields, relations, lookups and rollups, formulas, rows, then the rows' relation values, so a row links by name to a row made in the same call. A field is `{name, type}` plus that type's `weave_add_field` config keys, flat; a relation is a field with `type: "relation"` and `to`. Existing spaces, tables and same-typed fields are reused and listed in `existing`, so resending a whole spec after an error is safe; rows append, so a spec of rows alone is a batch create, and `skipExistingRows` skips a row whose Name the table already holds. An icon outside the inventory or an option colour weave cannot name is dropped and reported in `ignored` with its reason instead of blocking the table, field or option that wears it (on a second eval one refused table icon failed 42 fields, 20 relations and 96 rows), and a step that fails only because an earlier one did is not charged a second error. The spec runs first on an in-memory copy of the workspace, so `dryRun` returns every error at once with its path (`spaces[0].tables[1].fields[2]`) and writes nothing, and a spec with any error writes nothing either. The reply is one line: `{ok, created, existing, ignored, errors}`, where `ignored` names the config keys a field's type does not take, which `weave_add_field` drops without a word. On the 2026-10-02 eval a five-table budget workspace took 50 to 100 calls; the tool description carries a full example spec. Gate: `test/build.test.mjs`, plus the tool-count check in `test/agent-surface.test.mjs`.
