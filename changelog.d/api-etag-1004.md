- **API reads revalidate instead of refetching** (Issue #1004): every `GET` under `/api` that answers 200 now carries a weak `ETag` hashed from the exact body that request gets, with `Cache-Control: private, no-cache`, and a matching `If-None-Match` answers 304 with no body. The browser's own HTTP cache revalidates `/api/schema` and table pages on every navigation back, so an unchanged 50-row page costs a header exchange instead of its full body. Because the tag hashes the caller's own body, a tag from one member never answers another member's narrower read, and the auth wall still answers before any 304. Writes, `POST /query`, errors, `no-store` answers and cookie setters are left as they were, and private answers stay out of the shared compression cache. Gate: `test/api-etag.test.mjs`.
