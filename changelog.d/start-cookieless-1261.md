- New workspace setup now reaches its name step in a browser that refuses cookies. `/api/start` answers with a PostHog key wherever analytics is configured, so `boot()` started the consent banner before it drew the first step, and the consent code read `document.cookie` without a guard. In a sandboxed browser that read throws, and because only the `/api/start` fetch sat inside a `try`, the throw escaped and the page kept its initial "Loading weave…" status for good, with `GET /api/start` as the only request in the network log. Reading and writing the consent cookie now tolerate a browser that refuses it, and a failed analytics start can no longer stop the setup flow from rendering (Issue #1261).
