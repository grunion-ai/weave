- An HTML file that saves its own edits to `localStorage`, such as a deck that autosaves, now keeps them in weave. The `?view` page gets an in-memory `localStorage` and `sessionStorage` seeded from the file's saved snapshot; each `localStorage` change goes to the parent window, which accepts it only from that file's own frame and saves it, debounced, through the new `PUT /api/files/:id/storage` (`GET` reads it). A reload or another device starts from the saved snapshot. The page keeps its sandbox, so it still cannot reach the API or weave's cookies. The file bytes never change; the edits live in the file's page storage, capped at 5 MB per file, and a larger write is refused with a message (Issue #1176).
