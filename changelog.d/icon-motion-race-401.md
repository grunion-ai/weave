- **The icon-motion browser case no longer loses a 200 ms run to a loaded gate** (Issue #401): the first moving icon in the nav is a disclosure chevron whose run lasts 200 ms, and the case polled from the test side for the play classes after `hover()`. At load 80-135 the first poll landed after the run had ended, so "a hover plays the icon" failed on an unchanged main and the retry did not rescue it. A `MutationObserver` in the page now records each run as it starts, and the case reads that record: the hover plays exactly the hovered icon exactly once, the press plays the second icon, and the fixed wait before the press became a wait for the hover run to end. No product change. Tests: `test/icon-vocabulary-browser.test.mjs` (the motion case stalls on purpose for one run length after the hover, which fails the old polling read and passes the record).
