- **One vocabulary call for every list** (Issue #625): `weave_vocabulary` takes `sections: ["icons", "optionColors", "formulaFunctions"]` and answers each section keyed by name; `section` takes the same list or a comma string, so REST (`?section=icons,optionColors`) and the CLI (`weave vocabulary icons,optionColors`) answer alike. A query still searches the icons section, and a comma list of queries (`"wallet, bank"`) answers as `searches`. The single-section form is unchanged. On the 2026-10-03 disclosure eval agents spent 4 to 15 calls a run on one section each.
- **The build reply shows what computed fields computed** (Issue #627): `weave_build` returns `computed`, mapping each lookup, rollup and formula the build made (`"Budget/Category.Spending"`) to the first three values the grid shows for it, dry run included. Agents had run 3 to 10 `weave_query` read-backs per build to check them.
- **Layout rides the build** (Issue #628): a table in the build spec takes `fieldOrder` (the leading columns; the rest keep their order, in the schema and the default view), `hidden` (columns to hide in the default view; the minted Chip and Card stay hidden) and `sort` (`"Amount desc, Name"` or `[{field, dir}]`). A bad name is an error with its path. Agents had set these with one `Workspace/Tables` row write each, up to ten calls. The primer and AGENTS.md say so in a line each.
