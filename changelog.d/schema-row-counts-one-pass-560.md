- **A schema read counts rows in one pass** (Issue #560): `describeSchema` put each table's `entityCount` together by calling `listEntities(db.id)`, which walks the whole entity map and filters on `dbId`, so a page load cost tables times rows: about 50 tables by 6,078 rows on the weave workspace. `GET /api/tables/:id` and the search's table hits paid the same. A benchmark of v0.4.52 inside a 1 vCPU container measured a schema read at 45 to 67 ms at 8.4k entities, against under 5 ms at 4,389. The engine now walks `state.entities` once per schema read, buckets live rows by `dbId` into a Map (`#liveRowCounts`), and reads each table's count from it; `universalSearch` reads the same Map for its table hits, and builds it only when a table name matched. At 50 tables by 6,000 rows `describeSchema` drops from 30.4 ms to 0.89 ms a call. The count is still derived from the rows on every read rather than held as a maintained counter, so it cannot drift when a row is trashed, restored, purged or moved between tables. Gate: `test/schema-count-scan.test.mjs`.
