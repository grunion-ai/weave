- **A query computes each formula, lookup and rollup once per row** (Issue #1000): the sort called the field resolver inside the comparator, about 2n log2 n times, and the page read resolved every value again. The sort now computes each row's key once and sorts the pairs, and a query keeps a memo of computed values keyed by row and field, dropped when the query returns, so the next query sees every write. A value computed under a cycle or past the depth limit is never kept, and a kept value is reused only at the depth it was computed at or shallower, so results match the uncached read. Sorting 5,000 rows by a formula over a lookup went from 277.8 ms to 29.5 ms; the 1,000-row grid over a filtered rollup from Issue #999 went from 0.9 s to 77 ms. Gate: `test/computed-memo.test.mjs`.
