- One rail across several logins. The start page's cookie now holds every login this browser has signed in with, and `/start` lists the union of the workspaces those logins open, each row naming the login that opens it once there is more than one. "Add login" sends the person back to the provider with its account picker and adds the result; "Sign out" forgets them all. Every sign-in, at the start page or at a workspace, runs find my workspaces and sets a `wv_rail` cookie for the whole base domain naming the workspaces found, so a workspace host draws chips for workspaces it holds no session for; such a chip opens through `/api/start/open/<slug>`, which picks whichever held login has an account there. The rail's + button is now a menu: New workspace, Add login, Find my workspaces. An invite link opened in a browser that already holds a login offers "Accept as <login>" for each one, which redeems the invite with no provider trip, or "Use another login". A new device starts with the docs workspace only and rebuilds the rail one sign-in at a time; no server-side record links logins (Feature #279).
