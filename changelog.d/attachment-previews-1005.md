- **Attachment cells and covers load a small preview** (Issue #1005): a 4 MB phone photo in a small attachment cell used to download all 4 MB, because weave kept only the original. The web app now draws each PNG, JPEG or WebP upload to a canvas at upload (longest side 320 px, WebP, JPEG where the browser cannot encode WebP) and sends it beside the file; the file entry records it as `preview: { id, size, mime }`. `GET /api/files/<id>?preview` serves it, and answers the original for a file without one, so files uploaded earlier, and uploads from the REST API, MCP or CLI, keep working. Sheet cells and the entity cover ask for the preview with `loading=lazy` and `decoding=async`; the cover swaps to the original once it renders wider than the preview, and the viewer and lightbox always load the original. Previews count toward storage, travel in exports, imports and scoped backups, and go when their file or row is deleted. Gate: `test/file-preview.test.mjs`, `test/attachment-preview-browser.test.mjs`.
