- A write the database refuses (locked past the busy timeout, an I/O error) now answers `503` with code `not-saved` over REST, and the same code over MCP and the CLI, instead of a bare `500` (Issue #1667). The server also drops the refused change from memory, so reads answer the saved row and a later save never writes the refused value. A full disk keeps its `507` `storage-full` answer and rolls memory back the same way.
