- **A refused icon names the nearest inventory icons, and the vocabulary searches icons** (Issue #591): the 2026-10-02 agent eval had 17 refused writes for real Lucide names the curated inventory lacks (`lucide:building-2`, `handshake`, `tags`, `repeat`). The refusal said only "use lucide:<name> from the vocabulary", so the agent pulled the 4.4k-token list or dropped the icon. It now reads `Icon 'lucide:building-2' is not in the inventory; nearest: lucide:landmark (money), lucide:house (other). Search it with weave_vocabulary {section:"icons", query:"<word>"} (CLI: weave vocabulary icons <word>), or use a mark character`, and the write answers 400 with code `invalid`. Names rank by stem or substring, then a short synonym list for the words agents reach for first, then edit distance over the name or one of its words; nothing within reach means no suggestion rather than a misleading one. `weave_vocabulary` takes `section` (that section alone, as the CLI's `weave vocabulary <section>` already did) and `query` (with section `icons`, or alone): matches by name, category or synonym as `{name, category}`, or the nearest names marked `fuzzy`. REST: `GET /api/vocabulary?section=icons&query=build`; CLI: `weave vocabulary icons build`; an unknown section answers 400 on REST. The no-argument call is unchanged.
