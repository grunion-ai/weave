- **The release check's timeout fires on its own** (Issue #563): `createReleaseCheck` cut a hung request off with `AbortSignal.timeout`, whose timer is unref'd, so the abort landed only while something else held the event loop open. A real socket does hold it, which is why the hosted check was never affected, but `test/update-check.test.mjs` injects a fetch that just hangs, and on node 22.16 the loop drained first: five cases aborted with "Promise resolution is still pending but the event loop has already resolved", twice through the retry, and both node 22.16 legs of the `tests` workflow went red while both node 24 legs passed. The cut-off is now a ref'd `setTimeout` over an `AbortController`, cleared on every path, so it does not depend on what else the process happens to be doing. Gate: `test/update-check.test.mjs`, which runs the check in a bare child process and asserts the hung request is cut off there.
