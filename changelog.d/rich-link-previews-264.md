- **A pasted permalink unfurls** (Feature #264): `/w/<ws>/e/<id>` (and `Table#n`) answers 200 with the app shell and a server-rendered head instead of a bare 302. Slack, Messages and email show the workspace logo or the weave mark, `Issue #287 · <name>` as the title, the path `weave › Development › Issue` and the state and first fields (`Status Fixed · Severity Medium · Symptom Wrong data`), with Slack's `twitter:label`/`data` pairs. The tab reads the row before the app loads, the address moves to `#/entity/<id>` in place, and Back leaves in one step as before. Spaces and tables get the same at `/w/<ws>/s/<id>` and `/w/<ws>/t/<id>`, which the ⧉ on a space page and a table header now copy; the workspace root carries the head too. A new per-workspace setting, **Link preview before sign-in** (off by default; Workspace actions menu, `weave workspace link-preview`, `PATCH /api/workspace {"linkPreview": true}`), lets a signed-out fetcher read that head for a uuid permalink on a walled workspace and nothing more (a `Table#n` address stays walled, since public ids can be counted). The bundled raster mark is `public/brand/weave-mark-512.png`.
