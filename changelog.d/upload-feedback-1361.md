- Uploads show their progress and their failures: each file you pick or drop gets a tile in the field at once with **Uploading 40%**, then **Saving**, and the field is `aria-busy` until it lands (Issue #1361). Every file in a batch is tried on its own and one toast sums the batch up, naming the file that was not saved and why (Issue #1363). A failed file stays as a red tile with its reason and a Retry button, none for a file over the 10 MB limit, which offers **Choose another file** instead. A timeout or `504` reads the row again first, so a file the server stored before the answer was lost counts as uploaded. The document editor's upload button and the avatar picker share the same limit check and messages, the **+ file** picker takes several files (Issue #1365), error toasts carry a red accent and a new amber warning toast marks partial batches, and an error with no JSON body says the server is unavailable or returned an error instead of a bare status number (Issue #1364). The attach routes' `413` body now names its `limit` in bytes (Issue #1360).
