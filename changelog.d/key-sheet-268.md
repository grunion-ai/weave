- **A keyboard shortcut sheet on `?` and the rail's `?` chip** (Issue #268, and Kyle's report "command enter the sent work but there is not clue that this is possible in the ui"): `public/grid-keymap.js` carries a full spreadsheet keymap and nothing in the UI listed it; the only printed hint was the ⌘K footer, and the problem report's ⌘Return send had no mark at all. The keymap now exports `WeaveGridKeymap.bindings`, one row per key with the words the sheet prints and the presses that reach it, and answers `?` on a resting cell with a new `help` verb (inside an open cell `?` is still typed). `openKeySheet()` renders those rows, plus the handful of keys app.js owns (⌘K, ⌘⇧E, `/` or ⌘F, ⌘C/⌘V, ⌘Return in the report), through the existing `modal()`: `modal()` gained a show-only form (`onSubmit` null: one Done button, focus on it) and now returns focus to the element that opened it when the dialog still holds focus at close. `?` anywhere outside an input, a contenteditable or the document editor opens the same sheet, as does a new `#rail-help` chip above the theme toggle. The report panel prints `⌘↵` beside Send, and Send's tooltip names the key. The Handbook's keyboard guide gains the `?` row and a paragraph on the sheet; the bug report guide names ⌘Return. Gates: `test/grid-keymap.test.mjs` (at rest, ? opens the key sheet; the key sheet lists every key the keymap answers, in both modes; every row on the key sheet is a key the keymap still answers) and `test/key-sheet-browser.test.mjs` (? on a resting cell opens the sheet with every grid verb and Esc puts focus back; ? in an open cell is typed; the rail chip opens it and gets focus back; ? with nothing focused opens it and ? in the report note is typed; the report shows ⌘↵ beside Send), each browser case in light and dark.
