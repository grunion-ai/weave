- **Backup to weave cloud** (Feature #316): `weave backup --dest weave://<host>/<account>` and `WEAVE_BACKUP_DEST=weave://…` send the sealed nightly archive to a weave cloud account, authenticated with `WEAVE_BACKUP_TOKEN`, a `wv_` token from that account. The cloud stores ciphertext only. A cloud deployment with `WEAVE_BACKUP_BUCKET` set answers `PUT /api/backups/<archive>`, `GET /api/backups` and `GET /api/backups/<archive>`, keeps each account to thirty archives and `WEAVE_BACKUP_QUOTA_BYTES` (5 GiB by default), and refuses anonymous and cross-account callers. `weave restore --from weave://<host>/<account>[/<archive>]` pulls the newest or the named archive. `/api/health` names the destination kind. The new Handbook page **Backup to weave cloud** covers the destination, token, quota, restore and doors.
