- **A new row's choice is empty unless its field names a default, and the Default is a picker of the field's own options** (Issues #421, #422): Kyle, 2026-09-26, "select fields that don't have a blank or default value should not create a value: null (empty) unless otherwise specified" and "Default config should be a drop down selection of available options". The engine marked the first state `default` on every workflow field that marked none (in `addField`, in the normaliser every states edit runs through, and on the seeded four), and a type conversion filled an empty cell with that state, so every new row carried a status. Now a state is the default only when the author marks it (at most one), an empty cell converts to empty, and a state can be set back to empty from the API, the CLI or the cell's picker (a `—` row, as a select has). In the field dialog, select and multi-select lose the free-text Default box and workflow gains a Default: a picker over the field's own options or states with *No default* first, which follows a rename as it is typed and clears when its option is removed. The engine reads the default after the options in the same save, so a default that names a just-renamed option is accepted, and drops a select default whose option was removed. Existing workspaces: every workflow field made before this change stored `default: true` on its first state, so it keeps starting rows there; nothing is rewritten, and picking *No default* in the dialog clears it. Tests: `test/choice-defaults.test.mjs` (new, engine and REST), `test/choice-default-dialog.test.mjs` (new, dialog core), `test/choice-default-browser.test.mjs` (new, tray and grid); `engine`, `workflow-defaults`, `workflow-defaults-browser`, `table-move-duplicate`, `field-dialog-core`, `ui-contract` and `picker-browser` updated where they pinned the implied default or a state picker with no clear row.
