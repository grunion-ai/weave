- **A where compares a formatted number by its number** (Issue #617): `>`, `>=`, `<`, `<=`, `=`, `!=` and `in` read the stored figure of a number field, a number formula or a number across a relation, whatever its format, so `["Money", ">", 5000]` on a currency column painted `$12,000.00` matches that row in the engine, REST and `weave_query`. `contains`, `is-empty` and `not-empty` still read the painted text. Gate: `test/where-number-format.test.mjs`.
- **Deleting a row by its `Table#N` reference** (Issue #597): `deleteEntity`, `weave_delete_entity` and `DELETE /api/entities/<ref>` resolve the reference once and use the row's id after that. Before, a soft delete by reference trashed the row and then answered `not found`, and a hard delete answered `purged: true` with the row still in the table; both now answer the row they acted on, by id. A trashed row also answers its reference, so a second delete, a read and a restore by reference find it. Gate: `test/delete-by-ref.test.mjs`.
