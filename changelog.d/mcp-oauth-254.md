- **Agents sign in to a hosted instance through the browser** (Feature #254): with a provider configured (`WEAVE_OIDC_ISSUER` and `WEAVE_OIDC_CLIENT_ID`), `POST /mcp` (the default workspace) and `POST /w/<name>/mcp` serve MCP as an OAuth 2.1 protected resource, so `claude mcp add --scope user --transport http weave https://<host>/mcp` opens the provider's sign-in and needs no pasted token. `GET /.well-known/oauth-protected-resource` (and the `/mcp` and `/w/<name>/mcp` suffixed paths) publish RFC 9728 metadata naming the provider as the authorization server; a call without a credential answers 401 with `WWW-Authenticate: Bearer resource_metadata=...`. A provider access token is checked at the provider's userinfo endpoint (cached a minute by its sha256, never stored), its subject opens the account a `weave account link` invite pinned it to (the metadata asks for the `openid` scope alone, as the browser door does), and writes record `<account> via <client>` (`via oauth` for an opaque token). Unlinked subject: 403. Rejected token: 401. `wv_` tokens work on `/mcp` unchanged and `/api/mcp` keeps its contract. New: `WEAVE_MCP_ORIGINS`, other public origins the door answers on. Known limit: no RFC 8707 audience check, since Clerk does not bind tokens to a resource. Gates: `test/mcp-oauth.test.mjs`.
