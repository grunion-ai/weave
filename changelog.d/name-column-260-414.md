- **The Name column opens at 260px** (Issues #261, #414): Kyle's decision of 2026-09-26. Feature #233 opened Name at the mockup's 220px, and a thirty-character name such as "Quickstart for a new workspace" was cut off there. The dropped commit 41398c3 measured 240px leaving that name one pixel of room in Chromium's fallback face and chose 260px. The number moved inside Feature #233's width model (`NAME_WIDTH` in `public/column-resize.js`) rather than as the CSS `min-width` 41398c3 used, so the rest of that model holds: a stored view width or a resize still wins, every other type keeps its default, and the "+" column still takes the slack. The Handbook's width guide says 260. Three browser fixtures sat within 40px of their card and moved with it: `test/scroll-browser.test.mjs` opens its docked grid at 1900px instead of 1800 and the Σ-row case in `test/footer-rollups-browser.test.mjs` opens at 1480 instead of 1400, so each grid still fits its card and the page scrolls; the select fill in `test/grid-range-browser.test.mjs` scrolls Kind into the wrap's view before it grabs the fill handle. Gates: `test/column-layout.test.mjs` (Name and a computed Name default to 260), `test/grid-layout-browser.test.mjs` (Name opens at 260 beside the other types' defaults; in light and dark, a thirty-character name reads whole at the default, the "+" column fills the card, and a stored 180px wins).
