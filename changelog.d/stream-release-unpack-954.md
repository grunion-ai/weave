- **The supervisor streams a release download to disk** (Issue #954): `unpackCommit` read the whole codeload tarball into memory (19 MB, copied twice) and `unpackRelease` gunzipped it into one 44 MB buffer, so the idle production supervisor kept about 120 MB after each swap (166 MB private memory against about 50 MB for a bare Node process). The fetch body now runs through `zlib.createGunzip()` into `streamTar` (`src/backup.js`, sharing `readTar`'s header parsing), which writes each entry to the `.part` directory as it arrives. The path-escape refusal still runs per entry, and a truncated or corrupt archive is refused. On a 36 MB fixture one unpack now adds about 7 MB RSS instead of 127 MB.
