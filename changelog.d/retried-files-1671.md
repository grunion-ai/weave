- A test file that fails and then passes on its in-shard retry is recorded where every reader of the run looks. The shard result lists it under `retried`, the CI and PR gates name it in their aggregate and annotate the run with it, and after every main run the sheriff workflow appends a dated line to that file's `Error: <test file> flakes on main` row. Each file keeps one flake row: an Open or In Progress row takes the line, a Fixed one reopens, and a file with no row gets one. The sheriff counts an In Progress flake row as tracked, so it convicts no commit for that file. On 2026-11-11 `test/backup-stream.test.mjs` passed only on its retry in the green run of PR #922 and left no record, and the next run's red reverted PR #923 over it (Issue #1671).
