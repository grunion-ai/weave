- **A date grain sent as a word names the shape it needs** (Issue #590): the 2026-10-02 agent eval sent `{"grain":"month","format":"month"}` or `{"grain":"day","format":"iso"}` to `weave_add_field` 23 times in 32 runs. `normalizeGrain` read only an array or the tray's `{year, month, day}` flags, so a string collapsed to no parts and the engine answered "A grain with no date parts must keep a time of day", which names the wrong problem; agents then tried two or three shapes before landing on `["year","month"]`. A grain that is not a list or a flags object is now refused with `grain is a list of parts, e.g. ["year","month"] for a month or ["year"] for a year; parts are year, month, day`. A word is not accepted as an alias, because a bare "month" could mean month alone or year·month. The vocabulary's `dateGrainForm` says the same.
