- **Collapsing the nav no longer hides Activity, Workflows, Users and Trash** (Issue #909): `#app.nav-collapsed #sidebar { display: none }` removed the sidebar subtree, and the four pinned routes lived inside it, so a collapsed nav left only workspace switching and reaching Trash meant reopening the nav first. The 52px rail now carries the same four routes as icon buttons below the workspace avatars, behind a hairline, each with a tooltip label and an `aria-label`, the current one drawn as a filled `.ws-icon.active` tile carrying `aria-current="page"`. `#rail-routes` is a static slot in `public/index.html` that `renderNav` fills from the same `registryTable('workflows')` and `registryTable('users')` reads the sidebar's System group uses, so the two never disagree about which route is current. CSS shows the slot only under `#app.nav-collapsed:not(.nav-peek)`, which keeps exactly one visible copy of each route in every state: the sidebar group when the nav is open or peeking, the rail when it is collapsed. Labels under the icons stay out; that is the width decision the row left open. Gate: `test/ws-rail-routes-browser.test.mjs` (3 cases: every route visible and one click away in the collapsed rail, a divider above the group with the clicked route filled and the only one carrying `aria-current`, and no route visible twice with the nav open).
