- **A failing webhook marks its Workflows row Failed** (Issue #682): a webhook action was sent fire-and-forget, so a rule posting to a host that cannot resolve read Healthy forever. The engine now watches the settled request (5 second timeout): a non-2xx answer, a timeout or a network error sets the row's Health to Failed and its Health Reason to, for example, `POST hooks.example.invalid: ENOTFOUND`; the next run that succeeds reads Healthy with the reason cleared. The write that fired the rule never waits on the webhook and never fails because of it. `test/workflows-engine.test.mjs` covers a 500 then a 200, a refused connection and a listener that never answers, all on local listeners.
