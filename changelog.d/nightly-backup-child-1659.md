- **The nightly backup no longer holds up the server** (Issue #1659): `weave serve` built the whole archive (the `VACUUM INTO` snapshot, the tar and the seal) on the event loop that answers requests, so at 04:00 UTC every request and health check waited for it, about 250 ms for a 50 MB workspace and seconds for a large data directory. The timer now starts each run as a child process and keeps the child's result on the same schedule state, so `/api/health` and the `backup-completed` or `backup-failed` audit row read as before. `weave backup` on the command line still runs in its own process.
