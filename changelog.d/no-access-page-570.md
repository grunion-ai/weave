- **A refused sign-in no longer sends you back into the provider** (Issue #570): a provider account with no account here gets a `403` page, **No access to <workspace>**, that says a workspace admin can send an invite link and offers **Use a different account**. That button goes to the provider's `end_session_endpoint` (with `client_id` and `post_logout_redirect_uri` back to `/auth?signed-out=1`) when discovery names one, and otherwise starts a new trip with `prompt=login` (`/api/auth/oidc/start?fresh=1`, `select_account` added where discovery lists it), so the provider asks for credentials again instead of reusing its session. An invite opened as someone the server already knows (`409`) gets the same button, and its new trip carries the unspent invite. Every refusal page on the sign-in trip (expired or replayed trip, provider error, unverifiable token, provider down, spent invite, and the rate limit, which was bare JSON) now links back to `/auth?signed-out=1`; bare `/auth` sent a signed-out browser to the provider, whose own session signed it straight back in to the same refusal. A trip started under `/w/<name>` comes back to that workspace's sign-in page. Gates: `test/auth-oidc.test.mjs`, `test/auth-session.test.mjs`.
