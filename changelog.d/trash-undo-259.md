- **Selection-bar trash carries Undo, and ⌘Z steps it back** (Issue #259): ticking rows and pressing the bar's trash moved them at once, the toast read "Moved to trash 1 bug" with nothing to press, focus fell to `<body>`, and ⌘Z was bound to nothing although `POST /api/undo` worked; the 2026-09-12 audit trashed Issue #65 this way by accident. The engine keeps one undo entry per row, so a two-row trash leaves two, and the workspace's stack is shared with every other writer. The trash toast now carries **Undo** (the same `toast` action the row menu's delete uses), which steps back only the run of this gesture's own entries still on top of the stack and restores by id any row that run cannot reach: a registry row, whose trash is structure, or a row buried under a later write. Stepping back two blindly would have undone the later write and only one row. ⌘Z (Ctrl+Z) outside a text box, an open cell, a document editor and the popovers and dialogs the dock defers Escape to steps back the whole last gesture when it is still on top, else one entry, and redraws the grid in place through the same re-read a bulk write takes. The engine has no redo, so ⇧⌘Z stays unbound. After the trash the cursor lands on the row after the trashed ones (or the one before), and after Undo on the first row restored. The Handbook's selection-bar table and undo paragraph say so.
