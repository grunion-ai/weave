- **The Activity page loads one page, not the whole log** (Issue #850): `showActivity` asked `GET /api/activity` with no `limit`, and the route's `boundedLimit` falls back to `null`, so the view received every event the workspace had ever recorded and painted a `tr` for each one. On the weave workspace that is 26,067 rows and a 13.7 MB answer, and the hop from a table to `#/activity` took 10.0, 10.1, 10.4 and 11.0 seconds against 283 to 387 ms for a 1,300-row Issue table. `ACTIVITY_PAGE` (500) now rides on the request, the same page size the record panel already asked for, and the note says `Showing the newest 500.` whenever the feed holds more. The same four hops on the same database now take 161, 318, 316 and 298 ms with 500 rows painted. `activityFeed` keeps its `limit: null` meaning for the engine, the CLI and MCP, so no verb changed. Gates: `test/activity-page-size.test.mjs` (5 cases), `test/activity-page-size-browser.test.mjs` (4 cases, both themes).
- **Actor chips ask Users for the handles they draw** (Issue #850): `workspaceUsers()` read the whole Users table with `POST /tables/<users>/query {}` and cached it, which put a full table read behind the first Created By cell, record panel chip or Activity row on every page load. `actorChipEl` now names the one handle it needs, `workspaceUsers` collects the handles a paint asks for and `flushUsers` sends them as one `where: [['Name', 'in', want]]` query per microtask. Opening `#/activity` on the weave workspace sends one Users query naming four handles instead of a bare whole-table read. Grid, record panel and Activity chips resolve as before, in both themes. Gate: `test/activity-page-size-browser.test.mjs`, `test/system-fields-people.test.mjs`.
