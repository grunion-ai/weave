- `weave restore` and a migration to a cloud workspace read the archive as a stream: they decrypt and unpack it in one pass into a scratch directory, hashing each entry on the way, so a 200 MiB archive grows a restore by about 55 MiB where it took about 290 MiB, and grows the serving process by 114 to 148 MiB on a migration where it took 660 to 720 MiB (Issue #1663).
- Restore lands only the kinds of entry backup writes: workspaces, `files/`, `_hub.json` and `keystore.json`. An archive that carries a `-wal` or `-shm` file SQLite would replay into the restored workspace, any other entry, one entry twice, or an entry its manifest does not list is refused before anything lands (Issue #1724).
