- **Renaming a field carries its automations along** (Issue #1739): a schedule rule's where filter, the {{Field}} placeholders in action text and the row.Field source paths of an upsert-row action kept the old field name after a rename, so the rule read Ready while its next run filtered on a field that no longer existed. A rename now rewrites those references in the rule's Script, rolling the rename back puts them back, and a new name a rule could not read (a '.' in a filter or source path, a '}' in a placeholder) is refused with the rule named.
