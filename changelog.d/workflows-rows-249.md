- Automations are Workspace/Workflows rows (Feature #249): the row's Script holds the rule as JSON (`{table, trigger, actions}`, with names), On is the user's switch and gates every fire, State is computed setup (`Setup incomplete` / `Ready`, and a Setup incomplete row refuses to be switched On), and Health (`Healthy` / `Warning` / `Failed` / `No runs`, with Health Reason) and Last Run are stamped on every fire. A rule whose setup breaks while On stays On, is skipped and reads Failed with the reason. Existing rules move onto rows on open, adopting a hand-made row with the same Name on the same table. REST, MCP and the CLI keep their automation verbs.
