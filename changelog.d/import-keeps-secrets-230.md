- **An export imported back into its own workspace keeps the tokens, share links and sessions** (fixes Issue #230): since Feature #222 phase 0 the export strips account token hashes, view share tokens, sessions and invites, and import needs an admin token. A reader export was rechecked on 2026-09-28 across every GET route, the table query and the MCP export, workspace, accounts and schema tools, and none of them carries a token hash, a share token or a stored credential value. The round trip was still broken. An admin who exported a workspace and imported the dump back into the same workspace wiped every stored secret, because import replaced the whole state: the next call from that admin came back 401, every account token and share link stopped working, and every browser was signed out. Import now keeps what the dump leaves out. It matches accounts and views by id and restores each token hash and share token the dump omits, and it keeps sessions and invites for the accounts the dump still names. A secret the dump does carry wins over the stored one, an account or view the dump drops takes its secrets with it, and a dump imported into another workspace matches no ids and keeps nothing. Gate: `test/auth-wall.test.mjs` (1 new case: the export carries no `wv_`, `wvv_` or `wvs_` token, `tokenHash` or `shareToken`; after an admin import every token, the share link, a session and an invite still work, twice over; a dropped account and a dropped view lose theirs; a dump's own hash replaces the stored one).
