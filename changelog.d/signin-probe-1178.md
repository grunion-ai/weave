- `weave serve` checks its identity provider credentials at start and every 15 minutes. It sends a made-up code to the token endpoint with the configured client id and secret: `invalid_grant` means the provider accepted the client, while `invalid_client`, `invalid_scope` or `unauthorized_client` mean sign-in is broken. `/api/health` reads the result as `auth`. Anonymous callers see only `auth.ok`, and architects also see the status, the provider's error code and the time of the check. The top-level `ok` stays true, so a rotated secret never fails the Railway health check or rolls back a release, and the promote workflow writes one alert line when it lands a commit while `auth.ok` is false (Issue #1178).
