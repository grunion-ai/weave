- **A signed-out browser goes straight to sign-in** (Issue #569): with a provider configured (`WEAVE_OIDC_ISSUER` and `WEAVE_OIDC_CLIENT_ID`), a page behind the wall answers `302` to `/auth?next=<the page>` with `Cache-Control: no-store`, in place of the 401 page "This workspace requires authentication". `/auth` then sends the browser on to the provider, so a visit to `/` lands on the provider's sign-in with `?next` kept. API callers keep the JSON 401. The 401 page stays for an instance with no provider, where a token or a share link is the way in, and for a bad Bearer token on a page, since signing in is no answer to a wrong token. Gates: `test/auth-passkey-removed.test.mjs`, `test/auth-session.test.mjs`, `test/auth-wall.test.mjs`.
