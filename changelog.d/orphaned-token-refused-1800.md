- **A token whose issuing account was deleted is turned away** (Issue #1800): a signed-in caller whose role resolves to nothing, because the account that issued or added it was deleted or lost its own access, now gets `403` with code `access-removed` on every route except sign-in, `/api/health`, the start page, legal pages, public forms and static files. The app page shows the same refusal. Before this, under sign-in, such a caller skipped the role gate: an observer token could create spaces, rewrite the workspace, list and delete accounts, and over MCP list every tool and run the editor ones. The MCP door now also refuses a signed-in caller with no role, and a workspace with no accounts stays open. `test/security/access-matrix.test.mjs` gains a workspace-level HTTP twin for every caller with a door, and `test/security/orphaned-token.test.mjs` pins each refused route.
