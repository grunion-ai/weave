- **Reversing a scroll costs nothing** (Issue #938): the row window kept one buffer of drawn rows behind the reader and two ahead, picking the deep side from whichever way the reader was going, so a reversal mid-fling spent that one buffer and reached rows the window had dropped. It now holds two buffers on both sides and reads no direction at all: `windowFor` loses its `direction` argument, `travelFor` and the `win.dir`/`win.lastTop` state go with it, and arriving at a row from above draws the same window as arriving from below. PR #269 held the same shape and was reverted because the cut-off gate counted the extra rows parked below the fold; Issue #937 taught that probe to read only what the viewport shows, so the gate no longer moves with the window. Measured against `origin/main` on the same machine, every cut-off count is identical. Gates: `test/grid-window.test.mjs` (two cases: two buffers on both sides, and a stray `direction` argument moves nothing), `test/grid-window-feed-browser.test.mjs` (1 new case: the drawn rows reach as far behind the reader as ahead, whichever way the reader came; red on the old window at rows 354-428 against 374-448).
