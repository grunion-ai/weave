- **Credential values have a key store behind them** (Feature #213): `src/keystore.js` holds two stores behind the engine's key API. `file` is today's `keystore.json` and `keystore.key` pair, unchanged on disk, and stays the default on Linux, in CI and wherever a key file already exists. `keychain` keeps one macOS keychain item per key, named `weave:<workspace id>:<key>`, plus a `weave:keystore` item holding names, owners and sharing; it is the default on a Mac with no key file. `WEAVE_KEYSTORE=file` or `WEAVE_KEYSTORE=keychain` picks one by hand, `WEAVE_KEYCHAIN` names a keychain file, and `WEAVE_KEYSTORE` set to a path still means the file store at that path. Values reach `security` on stdin through `security -i`, never in a process argument list. Gate: `test/keystore.test.mjs`, one suite run against both stores (the keychain cases run on macOS against a throwaway keychain).
