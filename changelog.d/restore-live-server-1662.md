- `weave restore` refuses a data directory a running weave process holds, with or without `--force`. Before, `--force` under a live `weave serve` renamed a new file over the workspace while the server kept writing to the file it replaced, so every write made after the restore was gone at the next restart. Restore now tries to lock each `.db` in the directory and stops at the first one another connection holds open. The `-wal` and `-shm` files a server leaves when it exits without closing no longer count as a live server, so they no longer push an operator toward `--force` (Issue #1662).
- `weave restore` replaces hub routing (`_hub.json`) or an attachment blob already in `files/` only with `--force` when the archive's bytes differ, the rule workspaces and `keystore.json` already follow. A blob or routing file that matches byte for byte needs no `--force` (Issue #1669).
