- **Automation action `http-request`** (Feature #310): a Workflows rule calls an outside API with a method, a url whose path and query take templates, templated headers and a text or JSON body, and maps paths of the JSON answer onto fields of the firing record. `integration` names a System/Integrations record and the request goes through `integrationFetch`, so the key never enters the Script, the activity entry, the step output or the `key-used` audit entry. A url host that is not the integration's Host reads Setup incomplete, and the send checks again. With no integration the request is unauthenticated and passes the webhook address guard. The step output `{status, ok, body}` feeds later steps as `{{steps.N.body.id}}`; a non-2xx answer, a timeout or a refusal stamps Health Failed and stops the run. The automation engine gains `automationsSettled()`, which waits for runs still waiting on an answer. Gate: `test/http-request-action.test.mjs`.
