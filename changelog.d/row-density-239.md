- **Row density: Compact, Comfortable and Spacious, held to a declared height and saved with the view** (Feature #239, fixes Issue #440): every row is exactly 32, 44 or 72px, whatever its cells hold. The height is the `--wv-row-h` token and never a measurement: each value sits in one clip box (`--wv-cell-h`) from the grid's cell builder, the row rule is an inset shadow, and the row window reads the token instead of the measured cache from Issue #324. Only the height moves; text size and column widths are the same at all three. Spacious is new and shows two lines of a text value that carries marks (a plain text box stays one line), two lines of a description and a compact card; Compact and Comfortable show the card as a one-line chip. A multi-select or relation cell shows the whole chips that fit (two rows at Spacious) and a +N for the rest, and its hover pop shows them all. Density is a view setting beside filter, sort and fields: a pick autosaves into the live view, a new view starts at Comfortable, `weave_table_view`, `weave table view --density`, `/api/tables/:t/views/:v`, the schema document and the Workspace/Views row's Density column all read and write it, and the old per-browser `weave-grid-density:<table>` key is read once into a view that has none and removed. In development a painted row that misses its token logs the field type that grew it. Tests: `test/view-density.test.mjs` (new), `test/grid-density-browser.test.mjs` (row pitch in both themes, only height moves, whole chips, saved per view, the key handover, a Spacious flip at row 400 of 600), `test/grid-chrome.test.mjs` (caps are now exact), `test/ledger-grid.test.mjs`.
