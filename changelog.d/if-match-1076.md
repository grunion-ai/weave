- **Entity writes refuse a stale revision** (Issue #1076): `PATCH /api/entities/:id` takes an `If-Match` header carrying the `revision` the caller last read. When the row has moved on since, it answers 412 with `{ error, code: 'stale', entity }` and writes nothing; without the header it writes as before, so the CLI, MCP tools and scripts are unchanged. Table query rows carry `revision` as well. The grid sends the revision it drew each row from, so two people editing one cell no longer overwrite each other: the second commit repaints the cell with the first one's value and raises a toast naming the field, who changed it and the value that was not saved, with **Use mine** to commit it on purpose. A commit that cannot reach the server says so and leaves the typed text in the cell. Gates: `test/if-match.test.mjs`, `test/if-match-browser.test.mjs` (Issue #1076)
