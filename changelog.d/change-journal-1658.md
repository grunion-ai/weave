- **A write from the CLI or a stdio agent no longer makes the server reparse the whole workspace** (Issue #1658): every workspace `.db` now keeps a `changes` journal, one row per entity row written, filled by SQLite triggers inside the writing transaction whichever process writes, older weave versions included. The next request reads back only the rows written since the last journal row the server saw, and reparses a space, table or automation only where its stored JSON changed. On a copy of the 7,536-row weave workspace, a one-row write from another process used to cost the next request 44 ms and 7,597 `JSON.parse` calls; it now costs 1.8 ms and 2. The journal keeps its newest 1,000 rows. A process further behind than that, or one that opened the workspace before its journal held a row, loads the workspace in full once, as every refresh did before. The triggers make a bulk write, such as importing 10,000 rows, about a quarter slower.
