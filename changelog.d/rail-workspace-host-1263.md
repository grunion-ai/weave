- With a base domain set, clicking another workspace in the workspace rail opens it on its own host (`<slug>.<base domain>`) instead of serving it under `/w/<id>/` on the current host. The chip goes through `GET /api/auth/open/<slug>`, which hands the current session to the other host through the single-use sign-in code, so you arrive signed in; with no session that opens it, you land on the bare host and sign in there. A page link to `/w/<slug or id>/…` asked on another workspace's host now answers 301 to that workspace's host, so old links and bookmarks land right. Without a base domain nothing changes (Issue #1263).
