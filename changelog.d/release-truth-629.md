- **The release fold refuses an empty changelog fragment** (Issue #629): `scripts/changelog-fold.mjs` skipped a fragment whose text trimmed to nothing and deleted the file anyway, so that change would ship with no line in CHANGELOG.md or its GitHub Release. The fold now stops, names the empty file, and writes and deletes nothing. `test/changelog-fragments.test.mjs` fails a commit whose fragment is not a bullet with text.
- **A changelog fragment cannot ship work under an open security finding's number** (Issue #568): `changelog.d/mcp-inject-harness-499.md` shipped the MCP injection measurement harness in v0.4.53 under #499, the row for security finding S-22, which stays Open until its fix lands. The harness now has its own row, Feature #260, and `scripts/export-development.mjs` refuses to export a release while any fragment cites a security finding that is not Fixed. Correction to the v0.4.53 notes: the harness entry is Feature #260, not #499.
- **/api/health never reports a latest release older than the running version** (Issue #606): `update-check.json` sits beside the data on the volume, so after an upgrade the new build read the old build's answer and reported it for up to a day (weave.grunion.ai on 2026-10-03: version 0.4.56, latestRelease 0.4.54). The cache now records the version that wrote it, a different version asks GitHub again at boot, and an answer older than the running version reports the running version.
- **Correction to the v0.4.46 notes** (Issue #565): v0.4.46 was never tagged or published as a GitHub Release, but its Release row claimed that a 10-icon rating opened unclipped and that a rating column dragged narrower than its icons drew a compact `★ 7/10`. The fitted rating width shipped in v0.4.53 (Issue #404) and the compact form in v0.4.62 (Feature #235). Since v0.4.63 (Issue #614) a drag stops at the last icon, so only a rating whose icons pass the 320px fit cap draws the compact form.
