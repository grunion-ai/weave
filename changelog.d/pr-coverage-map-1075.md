- **The PR tier runs the browser tests that execute the code a pull request changes** (Issue #1075): the `pr` workflow picked browser tests by file name, so a one-file change to `src/routes.js`, `src/mcp.js`, `bin/weave.js` and eight other shared modules ran none beyond the 12 smoke files, and a `public/app.js` change ran 8 of 315; seven merged PRs went red on main and were reverted by the sheriff. `scripts/coverage-map.mjs` now runs the browser lane once with server (`NODE_V8_COVERAGE`) and Chromium client coverage and writes `test/coverage-map.json`: each executed function's line span in `src/`, `bin/` and `public/`, with the browser test files that ran it. `node scripts/ci-test.mjs pr-plan` turns the diff hunks into touched functions (innermost first, lines moved back to the map's commit) and selects the tests that ran them, ranked and capped at 80 browser files with the dropped ones printed. Files the map does not know keep name matching, and browser tests the map does not know always run. The new `coverage-map` workflow regenerates the map on GitHub runners every Monday, on demand and when the generator changes (eight shards, merged into one `coverage-map` artifact to commit), and `test/coverage-map.test.mjs` fails once more than 20 browser tests are missing from the map. Gates: `test/ci-test.test.mjs`, `test/coverage-map.test.mjs`.
