- **History follows an account across a rename** (Issue #699): a signed-in request set the actor to the account's name, and audit lines, activity, `createdBy`/`modifiedBy`, document revisions, comments, share links, invites and credential owners stored that string, so renaming `kyle` to `kyle.adriany` left every earlier line naming an account that no longer existed. A signed-in write now stores `account:<id>` (and `account:<id> via MCP` over OAuth), and every read path (the API, MCP, CLI and the web UI through them) renders the account's current name, or `removed account` once it is deleted. Lines written before this change are not rewritten and keep rendering the name they hold. Credential grants now record the account id too, and a credential owned or shared under an account's name still opens for that account. Plain writers (`web`, `local`, `mcp:<client>`, `bug-report`, `share:<label>`) are unchanged. Gate: `test/actor-account-id.test.mjs` (create `kyle`, write a row, a document and a credential, rename to `kyle.adriany`; history and reveal both follow the account).
