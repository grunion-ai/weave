The builder accepted if(upper(, saved it, and the first anyone heard of it was #ERR in every cell. Three directions below, on top of what this branch already lands. The premise for all three: a human and an agent author a formula through the same check. The engine produces one verdict; the dialog shows it and the API returns it.

Landed on this branch (not a proposal)
  • check() in src/formula.js: static validation of syntax, function names, field names.
  • Engine rejects a bad expression at save; a formula can no longer reference itself.
  • POST /api/tables/:id/formula-check + weave_check_formula (MCP) + weave formula check (CLI): validate and preview on a real row before saving. Documented in AGENTS.md; agent-surface gate green.
  • Dialog: live verdict line under the script (parse error in red, or = value from row 1), function chips land the caret inside the parens, the edited field's own chip is gone.
A

Chips that teach: groups + signature card

22 flat chips make the vocabulary look bigger than it is. Group them the way the grammar groups them, and let hover/focus show the one thing a chip never says: the signature, what it does, one example. The title-attribute tooltip today is invisible on touch and to agents reading the DOM.

B

Preview you can steer: row cycler + typed result

One preview row is proof the formula parses; it is not proof it is right. Let the author step through rows, pick the pathological one, and see what type came back. The number costume section below only applies to a numeric result, and today nothing says so.

The winThe null count is the real catch. A formula valid on row 1 and null on a third of the table is exactly the bug one preview row cannot show. One extra engine pass over N rows (capped, say 200) returns {nulls, errors, sampleByOutcome}, the same numbers an agent gets from the API to assert against.
FitExtends checkFormula with a scan: true option; the dialog and the CLI both consume it. Result-type badge falls out of the preview value's typeof, and it drives whether the number costume section renders at all.
C

The agent panel: the dialog shows its own API

Agent-first means the browser is never the only place a thing can be done, and the fastest way to keep that true is to print the equivalent calls where the human is standing. The dialog becomes its own documentation: what you just built by clicking is one command away from a script.

# 1 · check until ok:true (previews on a real row)

weave field add Deals Health formula --config '{"expression":"if([Amount] > 10000, \"major\", \"minor\")"}'

weave get Deals#1

The winEvery formula authored in the UI teaches the API loop; copy-paste is the onboarding. It also keeps the team honest: a panel that cannot express what the dialog just did means a browser-only gate slipped past the agent-surface suite.
FitStatic render from what the dialog already knows (table, expression). Same pattern later for selects, workflows, relations: the field dialog grows one shared "as an agent" footer.
D

Autocomplete in the expression itself

Chips are discovery; typing is speed. Once you know the vocabulary, [ should offer fields and two letters should offer functions, drawn from the same two lists the chips draw from, ranked by prefix.

The winMisspelled field names die at the keystroke instead of at the check. The error line stays live underneath; the two mechanisms answer different moments.
FitPlain contenteditable-free implementation: a positioned popover over the textarea using selectionStart, no editor dependency. Ship after A, whose enriched catalog supplies the ranked list.

Suggested order: A (catalog + card, smallest) → C (agent panel, pure render) → B (scan preview, one engine option) → D (autocomplete, reuses A). Each lands independently behind the existing suite; none blocks the branch that fixed the actual breakage.
