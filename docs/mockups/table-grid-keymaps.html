Three grids, all live — click into one and type. The seven-way study is retired. Your correction settles most of it: "check boxes should not need double click… on hover you can always single click into the edit, command click and shift click always de/select multiple." Putting selection on the modifiers takes it out of the plain click's way, so nothing has to be traded for it — which is what every earlier direction was paying for one way or another.

Settled by that correction, and true of both challengers below
  • One click edits, whatever the type. A checkbox flips, a select opens its picker, a date opens the calendar, text takes a caret at the click point — the same cellActivation map weave already ships.
  • Hover arms the cell first, so the control appears where you are pointing rather than living in every cell at once. The grid reads as a record at rest and as a form under the cursor.
  • ⌘-click toggles a row into the selection; ⇧-click takes the run from the last one. Neither ever competes with a plain click.
  • The keyboard arrives: Tab/⇧Tab along the row wrapping into the next, ↑↓ down the column, ←→ left to the caret, Return commits and drops a row, ⇧Return makes the next item.

Which leaves one open question, and it is the only thing the two challengers disagree about: can a row be selected without a mouse? H says the modifiers are enough. K spends Esc on a nav mode to say no.

NOW

What ships today

Feature #133 · Ledger

Every cell wears its editor permanently, so the grid always looks like a form. A click lands in the field it hit, ⌘-click opens the row in the side peek, and the #id ↗ link navigates. The grid answers to no keys at all and has no notion of a selected row — press Tab or ⇧Return in the demo and watch nothing happen.

WinsNothing to learn, nothing to build. One click has always reached every field, checkbox included — that part was never broken.
FitsReading a table and correcting a field in passing, which is most of what the grid is used for today.

        Recommendation

        Build H. Add K's mode only when something asks for it.

        H is the whole ask with nothing traded away, and it is small: hover CSS, two click modifiers, four key handlers. It keeps the ruling #133 already made, so no shipped behaviour reverses — the only thing that moves is ⌘-click, and it moves to ⌘Return where the keyboard wanted a peek anyway.

        K is H plus one escape hatch, and every line of H survives in it. That is the argument for not deciding now: build H, and if bulk work turns out to happen from the keyboard — or an accessibility commitment lands, where ⌘-click has no equivalent at all — Esc is still free and the mode drops in without touching anything already built.

        1. Hover + one-click edit. Cells render as values; :hover paints the control. The click path is unchanged from today, so activateCell is already correct.
        2. ⌘-click and ⇧-click select, with a row set on the table view and Esc to clear. Move the peek to ⌘Return in the same change so no gesture is ever ambiguous.
        3. Four key handlers — Tab, ↑↓, Return, ⇧Return. ⇧Return reuses state.inlineAdd; ⌘Return reuses peekEntity.
        4. Then the puck bar of #132, which now has a selection to act on and needs no new interaction model.
        5. K's mode, deferred. Costs nothing to leave out and nothing to add later.

        Still open

        QuestionWhy it matters
        Select without a mouse?The only thing separating H from K. ⌘-click has no keyboard equivalent, so H has nothing to offer anyone who cannot use a pointer — the accessibility answer, if you want one, is K.
        Does ⇧-click select a run of rows or a rectangle of cells?Rows is the smaller build and matches the puck bar of #132. Cells opens the door to fill-down and paste later, and cannot be retrofitted cheaply.
        Where does the docs-chips column sit in the Tab order?Documents are not cells. Skipping them keeps the Tab run tabular; including them makes the last stop a chip rather than a field.
        Does a hover-armed grid still read as editable?The reason every cell wears a control today. Worth watching for on a table of mostly-empty fields, where hover is the only thing saying they can be filled in.
