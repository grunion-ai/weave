# 🕸️ Weave

**A local, open-source, agent-accessible work platform** in the spirit of [Fibery](https://fibery.io): connected databases with relations, multistate workflows, lookups, rollups, formulas, automations — and a real markdown document on every entity, natively viewable as **MD, HTML, and PDF**.

Zero runtime dependencies. One JSON file of state. Three ways in: **web UI**, **CLI**, and **MCP server** for AI agents.

```
npm test        # 58 tests, node:test, no deps
node bin/weave.js serve --port 4400
```

## Why

Work platforms are either cloud SaaS (your data lives elsewhere) or too rigid (fixed schemas). Weave is a single small codebase you can read in an afternoon, storing everything in one human-readable JSON file, with every operation available to both humans (web UI) and agents (CLI + MCP + REST).

## Quickstart

```bash
git clone <repo> && cd weave
node scripts/seed.mjs                 # optional demo workspace
node bin/weave.js serve --port 4400 --data ./demo-workspace.json
# open http://127.0.0.1:4400
```

Data lives at `~/.weave/workspace.json` by default (`--data` flag or `WEAVE_DATA` env to override). Writes are atomic (tmp + rename).

## The data model

- **Spaces** group **databases**; databases hold **entities** with auto-incrementing public ids (`Task#3`).
- **Field types**: `text`, `number`, `date`, `daterange`, `checkbox`, `url`, `email`, `select`, `multiselect`, `workflow`, `relation`, `lookup`, `rollup`, `formula`.
- **Workflow fields** are multistate: named states in categories `not-started` / `in-progress` / `done` / `canceled`, with a default state and full transition history in the activity log.
- **Relations** are always bidirectional pairs (like Fibery): create `Task.Project ↔ Project.Tasks` in one call with `many-to-one`, `one-to-many`, `many-to-many`, or `one-to-one` cardinality. Reassigning a child updates both old and new parents. Deletes unlink cleanly.
- **Lookups** pull a field through a relation (`Task.Project Budget` ← `Project.Budget`).
- **Rollups** aggregate over a relation: `count`, `sum`, `avg`, `min`, `max`, `join` — including over computed fields on the far side.
- **Formulas**: `if(Estimate > 5, "large", "small")`, `concat(...)`, `round`, `days`, `today`, comparisons, and/or, etc.
- **Automations**: triggers (`entity-created`, `field-updated`, `state-changed` w/ target state) → actions (`set-field`, `append-doc`, `add-comment`, `webhook`) with `{{FieldName}}` / `{{Today}}` / `{{PublicId}}` templating.

## Documents: MD / HTML / PDF per entity

Every entity carries a markdown document. The server renders it natively:

| URL | Content type |
|-----|--------------|
| `/e/<id>/doc.md` | `text/markdown` |
| `/e/<id>/doc.html` | `text/html` — standalone styled page, dark-mode aware |
| `/e/<id>/doc.pdf` | `application/pdf` — US Letter, generated by Weave's own zero-dependency PDF writer (standard fonts, real Helvetica metrics, WinAnsi typography, multi-page) |

Documents support headings, lists, task lists, tables, code, quotes, links, images — and **entity mentions**: `[[Task#3]]` or `[[Task#3|label]]` resolve to live links in HTML and plain labels in PDF.

## Web UI

Table (sortable), Board (grouped by workflow/select, drag-and-drop between columns), and List views; entity pages with inline field editing, relation linking, doc editor with preview, comments, and activity; schema editor (add fields, relations, databases, spaces); workspace-wide search.

## CLI

```bash
weave schema
weave query Task --where '[["Project.Name","=","Apollo Launch"],["State","!=","Done"]]' --select 'Estimate,Assignee.Name'
weave create Task "Fix the flaky test" --values '{"Priority":"P1","Project":"Apollo Launch"}'
weave state Task#5 State "In Progress"
weave link Task#5 Assignee "Ada Chen"
weave doc append Task#5 --content "## Findings\n..."
weave doc export Task#5 --format pdf --out task5.pdf
weave search "onboarding"
weave csv Task > tasks.csv
weave export --out backup.json
```

Entities are addressable as `Database#publicId`, UUID, or name (with `--db`).

## Agent access (MCP)

`weave mcp` starts a Model Context Protocol stdio server (newline-delimited JSON-RPC). Register it with any MCP client:

```json
{ "mcpServers": { "weave": { "command": "node", "args": ["/path/to/weave/bin/weave.js", "mcp", "--data", "/path/to/workspace.json"] } } }
```

21 tools: schema introspection, query with relation traversal, entity CRUD, state transitions, linking, documents (read/replace/append), comments, search, CSV import/export, file attachments, spaces/databases/fields/relations/automations.

## REST API

`/api/*` — spaces, databases, fields, relations, entities, query (`POST /api/databases/:db/query` with `where`/`sort`/`select`/`limit`), state, link/unlink, docs, comments, automations, search, files, CSV import/export, JSON export/import. Errors map to 400/404/409 with `{error, code}` bodies.

## Design notes

- **No dependencies, ever**: markdown renderer, PDF writer, CSV parser, MCP server, HTTP router are all in-tree and tested (58 tests).
- **Computed fields are always fresh**: lookups/rollups/formulas resolve at read time with a cycle-depth guard, so there is no cache invalidation problem.
- **Single-writer model**: the server process owns the file while running; the CLI reads/writes the same file between runs. Don't run both against one file concurrently.
- **Not built** (the honest 20%): multi-user permissions & real-time collaboration, calendar/timeline/whiteboard views, reports/charts, external integrations (Slack/GitHub/Jira), forms, AI assist. See [docs/PARITY.md](docs/PARITY.md) for the full matrix.
